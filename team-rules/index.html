    Team Rules

    1. PR 작성 및 관리 규칙

    1. PR 크기: 하나의 PR에는 하나의 기능 추가 또는 버그 수정만 포함한다.
    2. 코드 변경량: PR당 변경 코드는 약 100줄 이내를 권장한다.
    3. 리뷰 인원: PR은 최소 2명의 팀원에게 리뷰를 요청한다.
    4. 리뷰 기한: 리뷰 담당자는 PR 생성 후 48시간 이내에 검토한다.
    5. 병합 조건:팀원 2명 이상이 승인한 PR만 main 브랜치에 병합한다.
    6. 브랜치 이름:feat/기능명, fix/오류명, docs/문서명 형식으로 작성한다.
    7. PR 제목 및 커밋 형식: 변경 사항을 구체적으로 작성하며, 커밋 메시지는 feat: 로그인 기능 추가와 같이 변경 유형과 내용을 명시한다.
    8. PR 설명: 모든 PR에는 What, Why, How I tested, AI use 항목을 작성한다.
    9. AI 사용 명시: AI를 사용했다면 AI 도구 이름, 사용한 파일 및 코드 위치(줄 번호), 직접 수정하거나 검증한 내용을 AI use 항목에 기록한다.
    10. 브랜치 정리: main 브랜치에 병합한 후 사용한 작업 브랜치를 삭제한다.

    2. 팀 협업 및 의사소통 규칙

    1. 주간 PR 담당자: 팀원 5명이 매주 돌아가며 PR 작성 담당을 맡는다. PR 작성자는 다음 주 PR 담당자에게 리뷰를 요청하며, 추가 리뷰어 1명도 지정한다.
    2. 메시지 응답: 팀 단체 채팅방의 메시지에는 24시간 이내에 응답한다. 확인했다는 표시만 남겨도 된다.
    3. 의견 충돌 해결: 팀원 간 의견이 갈릴 경우 각자의 근거를 GitHub Issue에 기록하고, 다수결로 최종 결정한다.
    4. 협업 책임: 각 팀원은 본인이 작성하거나 수정한 코드를 이해하고 설명할 수 있어야 한다.
